ADMIN MODEL / MIGRATION

Admin::User explicitly maps to admin_users, independently of existing ::User.
Fields: username, password_digest, active (default true), created_at, updated_at.
Required database fields, unique username index, normalized/nonempty username
check and nonempty password-digest check are installed by:
db/migrate/20261014000001_create_admin_users.rb (ActiveRecord::Migration[8.0]).
The checked-in schema diff contains only admin_users and its version change.
Existing mobile User schema, requirements, role/status semantics and relations
are unchanged. Existing unrelated schema-dump drift was excluded from the diff.

Username is stripped/lowercased via Active Record normalization. Password uses
has_secure_password with reset_token: false; minimum 12 characters and bcrypt's
72-byte maximum. Model and database enforce username uniqueness. No email,
roles, account-management UI, signup, recovery, invitations, MFA or OAuth added.
No database-backed Session model/table exists.

AUTH FLOW AND ROUTES

GET /admin/login -> Admin::SessionsController#new, dedicated admin_login layout.
POST /admin/login -> #create, outside protected Admin::BaseController.
DELETE /admin/logout -> #destroy, normal Rails CSRF protection.
GET /admin -> Admin::DashboardController#index, protected by Admin::BaseController.

authenticate_by uses bcrypt, including dummy work for unknown usernames.
Inactive accounts are rejected. Unknown username, wrong password and inactive
account receive the same generic failure, HTTP 422, with no password repopulation.
Auth responses and protected admin pages have Cache-Control: no-store.
Success resets the session before storing admin_user_id and redirects to /admin.
Logout resets the session and redirects to login. current_admin_user explicitly
queries Admin::User with active: true on each protected request. Deactivation or
deletion rejects subsequent access. HTTP Basic was removed, not retained as an
alternative. Password parameters remain covered by the existing passw filter.

Normal Rails encrypted CookieStore/key/domain are retained. No new cookie-based
API auth or JWT-based admin auth exists. Production HTTPS remains as configured.
CSRF checks were retained for login, logout and parking mutations. The rate limit
is 10 attempts/IP/3 minutes using a small process-local memory store; it is not
coordinated between workers and does not survive restarts. No new infrastructure.

SESSION NAVIGATION STATE

Forecast recent_locations is stored in the same host's normal session. The chosen
smallest safe behavior is to let reset_session clear it on login/logout. No old
session values are copied blindly or selectively retained. No cookie domain
widening or public host-routing changes were made.

:season/create, but now accepts POST instead of GET. The resource partial uses
