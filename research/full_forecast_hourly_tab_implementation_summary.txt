FULL FORECAST HOURLY TAB IMPLEMENTATION

Implemented Forecast Periods, Hourly, Discussion, Alerts in that order. Forecast Periods remains the default. All panels and all available hourly records are rendered in the initial response. The existing forecast-tabs controller is unchanged; tab selection performs no weather/network request.

The new private load_full_hourly calls the existing BaseForecaster#create_hourly_forecasts boundary once after a successful primary forecast. It unwraps NOAA's periods hash or accepts the OpenWeather array, distinguishes successful empty results from unavailable results, validates basic payload shape, and rescues/logs exceptions locally. Hourly failure does not change Forecast Periods, Discussion, or Alerts. No new API endpoint, service boundary, concurrency, or schema changes.

Hourly uses compact responsive rows: startTime-derived day/hour, optional icon, temperature/unit, short forecast, precipitation probability, wind, and humidity. Missing optional values display an em dash; legitimate zero temperature/percent values remain zero. Text is escaped. Timestamp formatting preserves the supplied UTC offset without converting it to server/browser local time; the panel explicitly avoids promising location-local time. Invalid timestamps show Time unavailable; missing offsets are labelled offset not supplied.

NOAA's first entry is labelled Period summary (with its supplied name if present), followed by Starts and the timestamp, and an explanation that it describes a broader period. The existing NOAA merge behavior is unchanged. Desktop lists scroll vertically within 65vh with keyboard focus support; smaller screens stack rows and use natural page scrolling. No lazy hourly icon loading or tab-selection fetch was added.

OPENWEATHER CACHE FIX

Only OpenWeather::Forecast::Alerts's cache type changed, from :hourly to :alerts. Existing store, 30-minute TTL, external query/request, converter, and response shape remain unchanged. Regression tests exercise actual services/converters with isolated in-memory caches and stubbed HTTP for both Alerts->Hourly and Hourly->Alerts. Repeated calls correctly reuse their separate cached payloads.
